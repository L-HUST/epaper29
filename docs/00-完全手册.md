## 1. 你要做的东西是什么

### 1.1 三层结构

墨水屏项目看起来"一块屏一块板"，其实是三层，**每层有不同的人负责**：

```
┌─────────────────────────────────────────────┐
│  你的代码（Application）                      │  你写：排版、翻页、协议
├─────────────────────────────────────────────┤
│  ESP32-S3 主控（MCU）                         │  算像素、发命令
├─────────────────────────────────────────────┤
│  屏模块的驱动板（Boost + Level Shift）         │  升压到 ±15V、电平转换
├─────────────────────────────────────────────┤
│  屏玻璃 + 驱动 IC（UC8176 / UC8151D）          │  产生波形、驱动粒子
└─────────────────────────────────────────────┘
```

### 1.2 每一层到底干什么

| 层 | 有什么 | 没有什么 | 谁做 |
|---|---|---|---|
| 屏玻璃 | 电泳粒子、行列电极、驱动 IC（跟着 FPC 走） | 没有升压、没有缓存 | 屏厂 |
| 驱动板 | 升压电路（3.3V→±15V）、电平转换、FPC 座、8pin 排针 | **没有 CPU、没有程序** | 模组厂（微雪） |
| 主控 | CPU、RAM、Flash、USB | 不会自己画图，要你的代码 | 你 |

**关键认知**：屏模块的"驱动板"只是电源和接线端子，它不懂你要显示什么。
命令、位图、时序，全部由主控发过去。

### 1.3 为什么屏不能直接插电脑

SPI 是**芯片之间**的总线：没有设备枚举、没有协议栈、没有"你是谁"的握手。
电脑的 USB 也不认识它。所以中间必须有一颗"会说 SPI"的芯片——也就是 ESP32。

### 2.2 每一项为什么在

- **屏模块**：必须带"驱动板"，不要买裸屏（只有软排线，要自己调升压，是硬件里最难的一环）。
  认准名字里有 **Module**，2.9 寸这块是 **V3**（V2 的例程也通用）。
- **主控**：必须是 **N16R8**。N16 = 16MB Flash（分区表按 16MB 划的，8MB 板子写不下），
  R8 = 8MB **八线** PSRAM（配置写的是 qio_opi，四线的 R2 识别不到）。
- **杜邦线母对母**：两头都是孔，插排针用。买成"公对公"就插不上。
- **面包板**：免焊插座，电容直接插。它存在的原因是**你不用焊**。
- **电解 + 瓷片**：屏全刷那 2.26 秒要抽一口大电，导线供不上会电压塌陷 → 花屏。
  电解管低频大电流，瓷片管高频，**两个都要，并联**。
- **USB 数据线**：必须是数据线。市面上很多是"只充电"的线，插上认不到串口。

### 2.3 不要买

| 不要买 | 原因 |
|---|---|
| HC-05 / JDY-31 蓝牙模块 | ESP32 只支持 BLE，不支持经典蓝牙 SPP，买了接不上 |
| 4.3 寸 e-Paper **UART** 模块 | 串口屏，板载 MCU，你拿不到 framebuffer，还更贵 |
| ESP32-S3 **WROOM-1 裸模组** | 没 USB、没稳压、没排针，不能直接插线 |
| 裸屏（只有 FPC 排线） | 要自己做升压板，第一次做必翻车 |

### 2.4 以后想上 4.2 寸，要加什么

**只加一块 4.2 寸屏（¥120~150），别的都不用买。** 原因见第 7.1 节。

## 3. 拿到硬件怎么装

### 3.1 接线表（S3 DevKitC-1 + 2.9/4.2 寸模块通用）

| 屏模块 | 方向 | S3 板 | 说明 |
|---|---|---|---|
| VCC | → | **3V3** | 不要接 5V |
| GND | — | GND | 必须共地 |
| DIN | ← | GPIO11 | SPI MOSI |
| CLK | ← | GPIO12 | SPI SCK |
| CS | ← | GPIO10 | 片选，低有效 |
| DC | ← | GPIO9 | 低=命令，高=数据 |
| RST | ← | GPIO8 | 低有效复位 |
| BUSY | → | GPIO7 | **高 = 忙**（和很多 LCD 相反） |

> 这 8 个引脚写在 `firmware/src/board_config.h` 的 S3 分支里，改那里就能换脚。

### 3.2 六步装配（每步都有检查点）

**第 1 步：把电容插到面包板上**

面包板两侧各有一排电源孔，同一排内部连通。把 `10µF 电解` 和 `0.1µF 瓷片` 的腿，
都跨插在 `+` 轨和 `−` 轨之间（两只是并联，不是串联）。

- 电解电容**有极性**：长脚是正，外壳白条纹带"−"的是负。接反通电会鼓包。
- 检查点：两只电容都跨在两条轨之间，没插到中间的信号区。

**第 2 步：把 3.3V 和 GND 引到面包板**

主控 `3V3` → 面包板 `+` 轨（杜邦线一根）
主控 `GND` → 面包板 `−` 轨（杜邦线一根）

- 检查点：用万用表直流电压档量 `+` 和 `−` 之间，应该是 3.3V 左右。**先别插屏。**

**第 3 步：把屏的电源接到面包板**

面包板 `+` 轨 → 屏模块 `VCC`
面包板 `−` 轨 → 屏模块 `GND`

- 检查点：屏没接反、没短路。

**第 4 步：接 6 根信号线**

DIN→11、CLK→12、CS→10、DC→9、RST→8、BUSY→7，一根一根接。

- 检查点：数一遍，**6 根都在**，且没有一根插到相邻的孔。

**第 5 步：插 USB，看板子**

先不烧程序，插 USB 看电源灯亮不亮、屏有没有反应。

- 检查点：屏此时通常是**上一次画面的残留**（墨水屏断电保画面），这是正常的，不代表坏。

**第 6 步：烧程序**

见第 6 章。

### 3.3 上电后你应该看到什么

烧完程序、复位后，屏上**直接出首页**（自检页默认关掉了，想要就打开 `SHOW_SPLASH`）：

1. 首页：`INK READER` / `UP n s` / `BOOT n` / `115200 8N1`，外面一圈黑框
2. 之后屏**不会自己刷新**（`REFRESH_EVERY_MS=0`），只有推数据时才动
3. 从电脑推一页文字：屏换成推的内容。全刷约 **2.3 秒**（屏幕会闪一下），
   文本命令走局刷约 **0.95 秒**（不闪）

串口应该打印：

```
=== Ink firmware (2.9inch 296x128 / UC8151D/SSD1680) boot #1 ===
framebuffer 4736 bytes, free heap 2xxxxx bytes
[ep29] init ok (SSD1680 + host LUT)
[ep29] refresh 4736 bytes, 2262 ms
READY. 文本: T|16,20,3|LINE1|LINE2   图像: python tools/push.py --help
[alive] 12 s  BUSY=0  splash=2263ms  refresh=0ms
```

**看到 `init ok` + `refresh ... 2262 ms` + 屏出图 = 全部跑通。**

判断技巧：正常全刷耗时恒定在 **2261~2263 ms**。如果这个数字是 0 或者只有几毫秒，
说明控制器压根没执行刷新——问题在初始化，不在显示数据。

**看到 `init ok` 且屏出图 = 全部跑通。**

### 3.4 故障对照表

下面这些**都是这台机器上真实发生过的**，按出现频率排序：

| 症状 | 真正原因 | 怎么办 |
|---|---|---|
| 全刷固定几毫秒、屏完全不动，`BUSY` 一直是 1 | 初始化序列不被接受：缺 `0x12` 软复位、`0x11` 数据入口、`0x44/0x45` 窗口、`0x4E/0x4F` 光标 | 照 `epd.cpp` 里 `e29_init()` 的顺序发，一条都不能少 |
| 刷新耗时正常（2.3 秒）但屏上一个点都不变 | 显存几何搞反：这块屏 RAM 是 **16 字节宽 × 296 行**（竖着存），不是 37 字节 × 128 行 | 见 `e29_build_mem()` 的映射 |
| 波形没下发、靠屏内 OTP | SSD1680 这颗必须由主机发 159 字节波形 | `0x32` 发 153 字节 + `0x3F/0x03/0x04/0x2C` 各发剩余几字节 |
| 推完图，屏过一会儿变回 `INK READER` 首页 | 打开串口时 DTR/RTS 会把板子复位，复位后重画首页 | 上位机先放掉 DTR/RTS，等 `READY.` 再发（`push.py` 已改） |
| 屏全白，串口 `BUSY=1` 一直不放 | BUSY 线没接或接错 | 查 GPIO7，量电压 |
| 花屏、条纹、只刷一半 | 缺去耦电容 / SPI 太快 | 确认两只电容真的在电源上；把 `EPD_SPI_HZ` 降到 4MHz |
| 串口一个字符都没有 | 数据线只能充电 / 插错口 | 换线；DevKitC 有两个 Type-C，试另一个 |
| 烧写失败 | 没进下载模式 | 按住 BOOT 再点一下 RST，然后重烧 |
| 编译报 `No such option '-D'` | 用了命令行 `-D` | PlatformIO 不认，改用 `-e 环境名` |
| 8 脚排线插拔几次后彻底不动 | 排线/座子接触不良 | 换排线。**先确认代码对不对**，别急着怪线 |
| 串口回 `ERR len=15000 expect=4736`，屏不刷新 | 上位机按 4.2 寸渲染了 15000 字节，设备是 2.9 寸 4736 字节 | 加 `--model 29`；`push.py` / `read.py` 现在默认就是 29 |

## 4. 软件架构

### 4.1 分层

```
┌──────────────────────────────────────────┐
│ 上位机 PC（tools/push.py, read.py）        │  Python：排版、渲染、打包、串口
└──────────────────┬───────────────────────┘
                   │ USB 串口 115200
┌──────────────────┴───────────────────────┐
│ 应用层  main.cpp                           │  协议解析、界面、状态机、休眠
├──────────────────────────────────────────┤
│ 驱动层  epd.h / epd.cpp                    │  SPI 命令序列、窗口、刷新、画图
├──────────────────────────────────────────┤
│ 配置层  board_config.h                     │  屏型、引脚、SPI 速率、功能开关
└──────────────────────────────────────────┘
```

### 4.2 每个文件的职责

| 文件 | 职责 | 你什么时候改它 |
|---|---|---|
| `board_config.h` | 屏型宏、分辨率寄存器、引脚、SPI 速率、按键/SD 开关 | 换屏、换板、改接线 |
| `epd.h` / `epd.cpp` | 驱动：`clear` / `draw_text` / `display_full` / `sleep` | 换控制器型号、调波形 |
| `main.cpp` | 串口协议、自检页、首页、休眠逻辑 | 加界面、加功能 |
| `include/font_ascii.h` | 5×7 ASCII 字库（自动生成） | 换字号（跑 genfont.py） |
| `platformio.ini` | 编译环境、分区表、PSRAM 类型 | 换板、换屏组合 |
| `tools/push.py` | 文字/图片/整本书 → 位图 → 串口 | 改排版、改字号 |
| `build.ps1` | 一条命令编译/烧写/看串口 | 基本不用改 |

**一句话理解分层**：`board_config.h` 说"接的是什么"，`epd.cpp` 说"怎么跟它说话"，
`main.cpp` 说"显示什么"，`push.py` 说"内容从哪来"。换屏只动第一层。

### 4.3 一次"推一页文字"的完整数据流

1. 你在 PC 上敲 `python tools\push.py --model 29 --port COM5 --text "..."`。
2. `push.py` 用 PIL 把字渲染到一张 296×128 的图上。
3. 转成 1bpp 位图：每行 37 字节，共 128 行 = **4736 字节**。
4. 加协议：`0xAA 0x55` + 512 字节头（前 4 字节 = 长度）+ 4736 字节数据 + 2 字节 CRC。
5. 串口发给设备（115200）。
6. 固件 `read_full_frame()` 收齐、校验长度和 CRC，通过后回 `0x06`。
7. `memcpy(epd.buffer(), frame, 4736)` —— 数据进了显存。
8. `display_full()` 发命令：0x24 写显存 → 0x22=0xC7 → 0x20 触发刷新。
9. 等 BUSY 变低（**2.9 寸全刷 2.3 秒**，4.2 寸约 5 秒）。
10. 刷完就断电；需要深睡时发 0x10 0x01。

理解这条链路，你就能定位任何问题落在哪一层。

### 4.4 为什么这么分层

- **换屏不动业务**：`EPD_WIDTH` 宏一变，`main.cpp` 里所有用宏的地方自动适配（我这次就是给 2.9 寸加了布局分支）。
- **换板不动驱动**：C3 和 S3 只是引脚不同，`epd.cpp` 一行没改。
- **排版放 PC**：固件里的内存和算力都紧张，而排版要反复调。放 PC 上改一次看一次预览，几分钟一轮；放固件里改一次要烧一次，几分钟一轮还看不到效果。

## 5. 关键设计的目的

这一段解释"为什么代码长这样"，看懂了你才敢改。

**1. 为什么是 1bpp（1 位 1 像素）**
墨水屏只有黑白（这块屏 4 灰阶是另外的寄存器）。1 位 1 像素时，4.2 寸 = 400×300/8 = 15000 字节，
2.9 寸 = 4736 字节。用灰度会翻倍到 2 bit/像素，内存翻倍、刷新更慢、残影更重，不值。

**2. 为什么 `1 = 白，0 = 黑`**
这是这款控制器（UC8176/UC8151D）的约定，和很多 LCD 相反。代码里都有注释，
写错了结果就是整屏反色。

**3. 为什么行宽要按 8 像素对齐（`EPD_STRIDE`）**
控制器按**字节**寻址，没有"第 3 个像素"这种说法。所以一行必须是整数个字节，
不足的高位要补白。4.2 寸 400/8 = 50 字节，2.9 寸 296/8 = 37 字节。

**4. 全刷和局刷为什么差 5 倍**
全刷是把粒子**强行推到**极限位置再回来，中间会黑白闪几次，所以干净但要 **2.26 秒**（2.9 寸）；
局刷是只把变化的像素推一下，不闪、**0.95 秒**，但会留下"上一个画面的影子"（残影）。
两者用的是**两套不同的波形表**：全刷 `WS_20_30`，局刷 `_WF_PARTIAL_2IN9`，
都要通过 `0x32` 命令由主机下发（这两块表都抄在 `epd.cpp` 里）。
局刷多了要补一次全刷清影子。

**5. 为什么 `sleep()` 必须在每次刷完调用**
刷的时候屏上加了 ±15V 高压。不刷的时候还加着，粒子会一直受力，
**久了会永久失效**。所以 `display_full()` 之后一定要 `sleep()`，这是硬性要求。

**6. 串口协议为什么要 512 字节头**
前 4 字节是长度，后面 508 字节是空的——**给未来留的位置**（比如加宽高、格式、页号）。
现在只用长度，但固件会拿它和 `EPD_BYTES` 比对，长度不对直接拒收。
这就是为什么 `--model` 和固件的屏型必须一致，否则报 `ERR len=`。

**7. 为什么要有 CRC**
串口传 15KB 必然偶发错位。没有校验时表现为"偶尔花一屏"，极难排查。
加了 CRC 后，错了就重传，问题变成显式的。

**8. 为什么排版不放在固件里**
见 4.4 最后一条。代价是"离不开电脑"，收益是能立刻看到效果。
要做成脱离电脑的设备，就得加中文字库（第 7.5 节）。

**9. 小字号为什么要"单色 hinting + 黑体"**

墨水屏只有黑白，PC 上渲染的抗锯齿灰度图最后必须**二值化**。这里有个隐蔽的坑，
2026-10-27 在实物上连续踩了两次（现象都是"文字不全、有的地方是断的"）：

| 做法 | 结果 | 原因 |
|---|---|---|
| 13px 抗锯齿 + 阈值 128 | ❌ 整笔消失 | 细横画只有 40% 覆盖率（灰度≈145），`145 > 128` 判成白，笔画整根没了 |
| 2 倍超采样 + 缩回 + 阈值 | ⚠️ 好一点但仍断 | 缩小后的灰度仍要过阈值，边缘笔画依旧时有时无 |
| **单色位图（`font.getmask(mode="1")`）** | ✅ 笔画完整 | 让 FreeType 直接给**hinting 后的 1 位位图**，横竖都落在像素格上，根本不过阈值 |
| 13px 仍偏挤 | 换 15px 明显更清楚 | 296×128 上 13px 已到中文极限；15px 配合小屏版式仍能放 5 行 |

实现要点（`tools/push.py`）：

```python
def paste_text(canvas, xy, text, font):
    m = font.getmask(text, mode="1")        # 单色、带 hinting
    ink = Image.frombytes("L", m.size, bytes(m))
    canvas.paste(Image.eval(ink, lambda v: 255 - v), ...)
```

两个容易踩的细节：

1. **字体按"排版字号"选，不按"绘制字号"选**。曾经写成 `load_font(size*2)`，
   于是"按 13px 算版面、用 26px 的雅黑画"，字直接溢出边界。现在用 `family_size` 参数分开。
2. **小字号（≤18px）优先黑体 SimHei**：笔画粗细均匀，缩放到像素格更稳；微软雅黑偏细。
   `--font` 可以强制指定，会覆盖这个策略。

**2.9 寸默认 15px，小屏版式下每页 5 行**——字号是实物对比 13/15/16 三档定的
（13px 复杂字会掉笔画，15px 笔画舒展）。

## 7. 怎么扩展

### 7.1 换屏（最简单，改一个参数）

```powershell
.\build.ps1 -Target 42 -Board s3 -Upload     # 换成 4.2 寸
python tools\push.py --model 42 --port COM5 --text "..."
```

**两边必须同时改**：固件的 `-Target` 和上位机的 `--model`。不一致就报 `ERR len=`。

为什么换屏不用改代码：分辨率、寄存器、显存大小全在 `board_config.h` 的三个分支里，
`epd.cpp` 和 `main.cpp` 只引用宏。

### 7.2 加按键翻页

硬件：两个 6×6 轻触开关，一脚接 **GPIO4 / GPIO5**，另一脚接 GND。

软件要点：

```
pinMode(PIN_KEY_NEXT, INPUT_PULLUP);          // 内部上拉
attachInterrupt(digitalPinToInterrupt(PIN_KEY_NEXT), on_next, FALLING);
// 中断里只置标志，不要在中断里刷屏
// 主循环里：置了标志 → 翻页 → 局刷 → 计数 +1
// 计数到 20 → 全刷一次清残影
```

### 7.3 加 SD 卡

硬件：SD 模块的 `CLK` 并到 GPIO12、`MOSI` 并到 GPIO11，`CS` 接 **GPIO13**、`MISO` 接 **GPIO14**。

要点：

- 屏是只写设备，MISO 一直空着，所以能共用总线。
- **SD 的 CS 必须上拉 10k 到 3.3V**，否则上电时卡会误进 SD 模式，之后一直初始化失败。
- 现在 `epd.cpp` 里 `SPI.begin()` 把 MISO 设成了 `-1`，共用总线时要改成 GPIO14，
  并且每次推屏前后成对调用 `beginTransaction / endTransaction`。

### 7.4 加蓝牙传书

**不需要买任何模块**，S3 芯片内置 BLE。

- 库用 `NimBLE-Arduino`（比默认 Bluedroid 省约 100KB Flash）。
- 手机端连上后，用自定义 GATT 服务发数据，设备写进文件系统。
- **蓝牙和深睡不能共存**：要么常开（约 1~3mA，电池撑不到一个月），
  要么"按键开窗"——长按 3 秒广播 60 秒，没连上就深睡。

### 7.5 加中文字库（脱离电脑的关键）

现在能显示中文是因为 PC 渲染好位图再推过去。要脱离电脑，固件里必须有字库。

- 格式建议：每个字 16×16 点阵 = 32 字节，**1 = 白，0 = 黑**（和显存同约定）。
- **只做书里出现过的字**（子集）：一本小说常用字 2000~3000 个，字库只有 80KB；
  全量 GB2312 是 216KB。
- 配一个索引：每个字 4 字节 Unicode + 4 字节偏移，按 Unicode 排序，固件里二分查找。
- 断行规则：中文按字宽 16、ASCII 按 10 累加；标点不能出现在行首。

### 9.2 编译产物在哪，怎么用

```
epaper29/firmware/.pio/build/<环境名>/
  firmware.bin      固件本体（烧到 0x10000）
  bootloader.bin    启动引导（0x0）
  partitions.bin    分区表（0x8000）
  boot_app0.bin     仅 S3 需要（0xe000）
  firmware.elf      带符号，调试用
```

- **正常情况下你不用碰它**：`-Upload` 会自动按地址烧上面几个。
- 想手动烧：`esptool.py --port COM5 write_flash 0x0 bootloader.bin 0x8000 partitions.bin 0x10000 firmware.bin`
- 想发给别人：`esptool.py merge_bin -o all.bin ...` 合成一个文件。
- `.pio/` 只是缓存，删了重编会自动重建。

### 9.3 日常怎么用：`push.ps1`

`push.ps1` 是包在 `push.py` 外面的一层：**不用记参数、不用查串口号**。

| 想要 | 命令 |
|---|---|

## 11. 这次调试的真实记录（照这个思路排查同类问题）

从"屏完全不动"到"能显示中文"，一共卡了两轮。写下来是因为**同样的坑你换一块屏还会遇到**。

### 11.1 当时的错误结论

一开始的现象是：上电刷不动、串口 `BUSY=1` 一直不放。我判断成"8 脚排线接触不良"，
还让你去跟客服要新排线。**这个结论是错的**——后来客服给了官方例程，一跑就出图。

教训：**在拿到"官方代码能跑"这个对照之前，不要断言硬件坏了。**
排线确实是经常出问题，但先花 10 分钟跑一遍厂商例程，能省掉一轮扯皮。

### 11.2 三处真正的 bug

**bug 1：初始化序列缺 5 条命令**

原来的顺序（错）：
```
0x00 1f 0d / 0x01 03 00 2b 2b 09 / 0x06 07 07 17
0x61 80 01 28 01 / 0x50 97 / 0x82 22 / 0x04
```
这个序列看起来像 UC8151 的写法，但**这块屏是 SSD1680**，寄存器含义不一样。
官方序列是：
```
0x12                        软复位，然后等 BUSY
0x01 27 01 00               驱动输出
0x11 03                     数据入口（X/Y 递增）
0x44 00 0F                  窗口 X：0~15 字节
0x45 00 00 27 01            窗口 Y：0~295 行
0x21 00 80                  显示更新控制
0x4E 00 / 0x4F 00 00        光标归零
0x32 + 153 字节波形          下发全刷波形
0x3F / 0x03 / 0x04 / 0x2C   波形里剩下的 6 个字节
```

**少 `0x11` + `0x44/0x45` 的后果**：窗口是 0×0，你往里写 4736 字节全被丢掉。
CPU 侧看不出来——SPI 照样发完、`delay` 照样等完，所以**现象是"刷新耗时 3.5 秒，
屏一动都不动"**。这个现象非常有迷惑性，很容易判成硬件坏。

**bug 2：显存几何反了**

我原来按"296 像素宽、每行 37 字节、128 行"写。这块屏的 RAM 实际是：
**16 字节宽（128 像素 = 短边）× 296 行（长边）**，也就是竖着存。

所以刷屏前必须把横向画布转成竖向显存。映射照官方 `GUI_Paint` 的 `rotate=270`：

```
用户像素 (x, y)  →  RAM[ (295 - x) * 16 + y/8 ]  的  第 (0x80 >> (y%8)) 位
```
代码在 `epd.cpp` 的 `e29_build_mem()`。

**bug 3：靠屏内 OTP 波形**

SSD1680 这块必须由主机发波形。不发的话，`0x22` 触发的是"空动作"，
看起来很勤快地跑了 2.3 秒，实际什么都没推。两套波形表（`WS_20_30` 全刷、
`_WF_PARTIAL_2IN9` 局刷）都抄进了 `epd.cpp`。

### 11.3 上位机侧的两个坑

- **打开串口会复位板子**：ESP32-S3 的 USB-CDC 一 open，DTR/RTS 拉起来就是复位脉冲。
  所以 `push.py` 打开后先 `dtr=False, rts=False`，再**等设备打出 `READY.`** 才发数据。
- **"设备返回"必须是 `OK frame`**：固件刷完屏会先打一行 `[ep29] refresh ...`，
  再打 `OK frame`。只读一行的话，会把开机日志当成成功回复——我第一次就是这样被骗过去的。

### 11.4 判断"到底是哪一层坏了"的方法

| 观察 | 说明 |
|---|---|
| 全刷耗时恒定 2261~2263 ms | 控制器在跑波形，**初始化对了** |
| 全刷耗时 0~几毫秒 | 初始化没被接受，别去查数据 |
| `BUSY` 空闲时是 0，刷新期间变 1 | 正常 |
| `BUSY` 一直是 1 | 控制器卡住（多半是初始化序列里发错了一条） |
| 屏全白 + 耗时正常 | 数据没进显存，查窗口和几何 |
| 屏显示但内容错位/转 90° | 只差映射方向，改 `e29_build_mem` 里两处符号 |

一句话：**先看耗时，再看 BUSY，最后才怀疑硬件。**

## 12. 附录 A：电源、省电、残影、排查顺序（和尺寸无关）

这一节原来散在两篇单独的硬件/调试文档里，内容重复且以 4.2 寸为主，现已合并到这里。

### 12.1 电源：花屏的头号原因

墨水屏刷新时由板上升压电路把 3.3V 升到 ±15V 左右，**瞬时电流冲击大**。供电不稳的典型表现是花屏、条纹、复位失败、偶发刷不动。

必须做：

1. 屏模块 **VCC–GND 就近并 10µF 电解 + 0.1µF 瓷片**（2.9 寸也建议加，成本几毛钱）
2. USB 线别又细又长，劣质线压降大
3. 电池方案：3.7V 锂电 → LDO（ME6211 / XC6206 3.3V）→ 屏模块；
   要长待机选静态电流 <10µA 的 LDO（TPS7A02）
4. 产品化建议给屏电源加 **MOS 开关**：不刷新时彻底断电，比只发 sleep 命令更省

功耗参考：

| 状态 | 电流 |
|---|---|
| 2.9 寸全刷（2.26 秒） | 平均 10~20mA，峰值更高 |
| 局刷一页（0.95 秒） | 约为全刷的 1/3 |
| 屏已 sleep | < 1µA |
| ESP32-S3 deep sleep | 约 10µA（模块不同差异大） |
| ESP32-S3 运行 + WiFi | 40~100mA |

### 12.2 省电与寿命

| 做法 | 效果 |
|---|---|
| 刷完 `sleep()`（2.9 寸：`0x10 0x01`） | 屏从 mA 级降到 <1µA |
| MCU 进 deep sleep | 从几十 mA 降到 µA 级 |
| 屏电源加 MOS 开关 | 最省；**唤醒后必须重新 init** |
| 拉长刷新间隔 | 寿命约 100 万次，每 10 分钟刷一次 ≈ 19 年 |
| 别长期加高压 / 别暴晒 | 防不可逆损伤 |

定时唤醒模板（`main.cpp` 里已有）：

```cpp
esp_sleep_enable_timer_wakeup(30ULL * 1000000ULL);
esp_deep_sleep_start();      // 醒来等于重启，从 setup() 再来一遍
```

"起来→刷新→睡回去"的产品循环：把要显示的内容存到 NVS，`setup()` 先读出来画一遍，
再去取新数据；没有新数据就直接睡，别空刷。

**阅读器不要用深睡翻页**：唤醒 + init + 全刷要 3 秒以上（4.2 寸要 6 秒）。读书时保持常开，无操作 5 分钟后再休眠。

### 12.3 残影管理（阅读器的核心工程问题）

连续局刷一定累积残影，官方明确说严重时**不可修复**。

```
翻页 1 次   → 局刷（0.95 秒，不闪）
每 20~50 页 → 全刷（2.26 秒，闪几下）   ← 清残影，保命
```

固件里的两个入口：局刷走串口 `T|...`（`display_partial_margin`），全刷走串口 `F`。
上位机侧建议维护一个计数器，每 20 页自动插一次全刷。

注意：

1. 局刷窗口 x 起始必须按字节对齐（`x/8`，固件已处理）
2. 局刷区域别贴屏幕边缘，留 6~10 像素
3. 局刷后切回全刷要先重新初始化（`s_need_reinit`，固件已处理）
4. 长期显示同一幅图（>24 小时）建议定期刷新，避免"烧屏"

### 12.4 温度

- 工作温度 **0~50℃**，屏内波形**不带温补**
- 低于 0℃ 会变慢、变浅、残影加重
- 户外用要选带温补的屏（贵 30%+），或加加热膜（不推荐，功耗大）

### 12.5 上电排查顺序（2.9 寸版）

```
① pio run 能编译通过？
② 串口有 [ep29] init ok 和 framebuffer 4736 bytes？      （数字对不上 = --model 和 EPD_MODEL 不一致）
③ 全刷耗时是不是 2261~2263 ms？                          （几毫秒 = 初始化没被接受）
④ BUSY 空闲时是不是 0、刷新期间变 1？                     （恒 1 = 控制器卡住）
⑤ 屏有没有任何变化（闪一下也算）？                         （手机慢动作录像看）
⑥ 方向/颜色对不对？                                    （不对 = e29_build_mem 的映射方向）
⑦ push.py 推一页能不能整屏刷出来，回 OK frame？
⑧ 串口 T|10,20,2|HELLO 能不能局刷（约 950 ms）？
```

⚠️ **8 脚接口没有 MISO，读不了状态寄存器**。网上很多排查文档让你看 `STATUS=0x00`，
在这块屏上没有意义，别在这上面浪费时间——**只看 BUSY 和刷新耗时**。

### 12.6 元器件关键词（淘宝/立创直接搜）

- 墨水屏：`2.9寸墨水屏模块 SPI 296x128 微雪 V3`
- 主控：`ESP32-S3 SuperMini N16R8`（要 PSRAM 就选 N16R8）
- 排线：`1.27mm 8P 双头 同向 排线`（备用一根，接触不良是常见故障）
- 电容：`10uF 0805` + `0.1uF 0603`
- LDO：`XC6206P332`（便宜）/ `TPS7A0233`（超低静态）
- 电池：`3.7V 锂聚合物 1000mAh 带保护板`

### 12.7 以后想上 4.2 寸，要补什么

2.9 寸跑通不代表 4.2 寸能直接亮，两者是**不同控制器**：

| | 2.9" 296×128 | 4.2" 400×300 |
|---|---|---|
| 控制器 | SSD1680 | UC8176 |
| 显存 | 4736 字节 | 15000 字节 |
| 显存几何 | **竖存** 16 字节 × 296 行 | 横存 50 字节 × 300 行 |
| 初始化 | 9 条（0x12/0x01/0x11/0x44/0x45/0x21/0x4E/0x4F + 波形） | 另一套（0x00/0x01/0x06/0x61/0x50/0x82/0x04） |
| 波形 | 必须主机下发（`0x32`） | 屏内 OTP 一般够用，不满意再下 LUT |
| 全刷 | 2.26 秒 | 约 5 秒 |

要动的地方：`board_config.h` 的 `EPD_MODEL=42` → 核对 `EPD_RES_*` / `EPD_VCOM_DC`；
`epd.cpp` 走的是通用路径（`cmd/data` + `set_window`），不需要 `e29_*` 那套。
4.2 的完整产品化方案见 [`archive/90-4.2寸方案.md`](archive/90-4.2寸方案.md)（归档，非主线）。

### 12.8 自制驱动板（量产省钱）

抄官方原理图，要点：

1. **升压电路**：3.3V 升到 ±15V（VGH/VGL/VSH/VSL），常用 TPS65186 或分立电感方案
2. **电平转换**：5V 主控必须转，3.3V 主控可直连
3. **FPC 座**：按屏型号，2.9 寸和 4.2 寸间距/pin 数不同，买前核对
4. **电源开关**：屏电源加 MOS，不刷新时断电（唤醒后必须重新 init）
5. 打样：嘉立创 5 片 100×100mm 以内约 ¥5~10

量产大致成本（1K 量级，仅供参考）：裸屏 ¥35~60 + 驱动/电感/电容 ¥5~8 + PCB ¥1~2
+ 主控（直接贴 ESP32-S3）¥6~10 + 外壳 ¥4~8 ≈ **¥55~90**。

## 13. 附录 B：使用与原理速查

这一章回答"这东西到底怎么运转"的 6 个基础问题，都是实际被问到过的。

### 13.1 `build.ps1` 和 `push.ps1` 改变的不是一回事

| | `build.ps1` | `push.ps1` |
|---|---|---|
| 改变什么 | 芯片里运行的**程序** | 屏上显示的**那一页** |
| 多久跑一次 | 改代码才跑（分钟级） | 每天都能跑（秒级） |
| 不跑会怎样 | 设备里还是旧程序，照跑 | 屏上保持最后那页，断电也不丢 |
| 类比 | 刷机 / 装 App | 发一条微信 |

**关键：推图不会改变固件。** 它只是把 4736 字节塞进屏的显存。

### 13.2 每个文件干什么

**烧进芯片里的：**

### 13.3 一次推图的完整链路

以 `.\push.ps1 "第一行|第二行"` 为例：

```
push.ps1  →  tools/push.py
  ① Pillow 排版渲染 → 1bpp 位图 4736 字节
  ② 打包：512 字节头（前 4 字节=长度）+ 位图 + CRC16
  ③ 发 0xAA 0x55 并等设备回 0x06（ACK）
        ↓  USB-CDC / 115200
main.cpp  read_full_frame()
  ④ 收齐 4736 字节，校验长度和 CRC，不通过回 0x15（NAK）
  ⑤ memcpy 进 epd.buffer()
  ⑥ display_full() → epd.cpp 的 e29_show()
  ⑦ e29_build_mem()：横放 296×128 画布 → 竖存 16×296 显存
  ⑧ SPI 发 0x24（新图）、0x26（旧图）、0x22=0xC7、0x20
  ⑨ 等 BUSY 拉低，约 2.26 秒
  ⑩ 串口回 "OK frame"
```

**任何一环出问题，症状都不一样**：回 NAK 是数据错，屏不动但耗时正常是显存几何错，耗时只有几毫秒是初始化没被接受。

### 13.4 `-File` 和 `-Book` 的区别

用同一个 12 行文本实测：

| | `-File` | `-Book` |
|---|---|---|
| 一屏怎么填 | 所有行塞进一屏，字号自动缩 | 按字号/行高自动分页 |
| 实测结果 | 12 行缩成小字，**看不清** | 自动分页，每页 5 行，字正常 |
| 页眉 | 无 | 有（`文件名 p1/13`），小屏不显示底部百分比 |
| 换页 | 不支持 | `-Page 3` |
| 适合 | 便签、口令、短清单（**≤5 行**） | 长文、书 |

```powershell
.\push.ps1 -File notes.txt              # 不分页
.\push.ps1 -Book novel.txt -Page 3      # 分页
```

### 13.5 四种翻页方式

**① 键盘翻页（最像阅读器）**

```powershell
.\.venv\Scripts\python.exe tools\read.py --book novel.txt --port COM4
```

默认按 2.9 寸（296×128）渲染，不用手写 `--model`；跑 4.2 寸才加 `--model 42`。

| 键 | 作用 |
|---|---|
| `n` / 空格 / `→` | 下一页 |
| `p` / `←` | 上一页 |
| `f` | 强制全刷一次（清残影） |
| `s` | 让设备休眠 |
| `q` | 退出 |

按键**不用回车**，按一下生效。

**② 一条命令一页**

```powershell
.\push.ps1 -Book novel.txt -Page 1
.\push.ps1 -Book novel.txt -Page 2
```

**③ 串口文本命令（最快，但只支持 ASCII）**

```
T|10,20,2|HELLO|SECOND LINE
```

固件用自带 5×7 字库排版、走局刷（约 0.95 秒，不闪）。中文必须走 `push.py`。

**④ 手动清残影**：串口发单个 `F`，固件做一次全刷。

### 13.6 烧写到底写了什么，为什么按不按 BOOT 都能烧

Flash 里是**三段**，不是一整块：

| 地址 | 内容 | 谁的 |
|---|---|---|
| 芯片内部 ROM | bootloader | **出厂固化，改不了**；负责 USB 下载和启动 |
| `0x0000` | `bootloader.bin` | 编译产物，可覆盖 |
| `0x8000` | 分区表 | `partitions_16mb.csv` |
| `0x10000` | **我们的 app**（约 318 KB） | 每次 `-Upload` 覆盖这一段 |

**USB 为什么还能用**：ESP32-S3 芯片内部就带 **USB Serial/JTAG 硬件外设**（设备管理器里 `VID_303A PID_4001`），ROM 和我们的程序都能用它。我们只是调用 `Serial.begin()`，底层由 Arduino core 配置 CDC。板子上另一个 USB 口走的是 CH343/CP210x 转串口芯片，两条路都能烧。

**为什么现在不用按 BOOT+RST**：DevKitC-1 板上有两管自动复位电路，esptool 用 DTR/RTS 去拉 EN 和 IO0（上传时那句 `Hard resetting via RTS pin...` 就是它）。需要手按的只有这几种：

| 情况 | 现象 |
|---|---|
| 板子没有自动复位电路（裸模组/劣质板） | 卡在 `Connecting...` |
| **串口被别的程序占着** | `Could not open COM4, port is busy` |
| USB 线只有充电 | 根本认不到串口 |
| 转串口驱动没装 | 设备管理器黄色感叹号 |

### 13.7 WiFi 和蓝牙在固件里吗

**硬件在芯片里，代码没进固件。**

证据看体积：我们的 app 约 **318 KB**；带 WiFi 的 ESP32-S3 Arduino 固件通常 **900 KB ~ 1.2 MB**。
链接器（`--gc-sections`）把没被调用的 WiFi/BLE 库整段丢掉了——我们只用了 `Serial`、`SPI`、GPIO。

想开的话：

- WiFi：`WiFi.begin("ssid", "pass")`，几行代码
- 蓝牙：建议 `NimBLE-Arduino`（比默认 Bluedroid 省约 100 KB）
- ⚠️ 一开 WiFi，功耗从 mA 级跳到 **40~100 mA**，现在"推完就睡"的低功耗设计会被破坏，电池方案要重算
